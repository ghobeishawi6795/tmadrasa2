# دور سی‌وسوم — مرحله ۶ باگ‌گیری: سوئیچر حساب + موبایل (۲۰۲۶-۰۹-۱۹) — v77

## 🔴 ۱) هویتِ اشتباه بین تب‌ها (باگ واقعی، از ترکیب «ماندگاری ورود» + «سوئیچر حساب»)
از v73 سشن فعال توی `localStorage` نگهداری می‌شه، یعنی **همه‌ی تب‌های باز سایت یک سشن مشترک دارن**. سناریو: تب A روی داشبورد مدیر باز، تو تب B به حساب معلم سوئیچ می‌کنی → تب A هنوز ظاهر «مدیر» رو داره ولی هر درخواستش (`apiFetch` توکن رو تازه از storage می‌خونه) به‌عنوان **معلم** احراز هویت می‌شه. نتیجه: خطاهای ۴۰۳ گیج‌کننده، یا بدتر — ارسال پیام، انتشار آزمون و… با هویتی غیر از چیزی که روی صفحه می‌بینی. (سرور همیشه درست اعمال می‌کرد؛ مشکل عدم‌تطابق UI و هویت بود.)
- **فیکس:** `api.js` شنونده‌ی `storage` گرفت: اگه تب دیگه‌ای سشن فعال رو به حساب دیگه‌ای تغییر بده یا پاکش کنه (خروج)، این تب reload می‌شه و گاردهای صفحه دوباره به داشبورد درست / صفحه‌ی ورود می‌برنش. رفرش توکن برای همون حساب، صفحه‌های ورود و کلیدهای نامرتبط reload نمی‌زنن.
- تست شد با شبیه‌سازی دو تب روی storage مشترک (۶ سناریو: همان حساب، رفرش توکن، سوئیچ، خروج، کلید نامرتبط، صفحه‌ی ورود).

## 🟡 ۲) ✕ ی کوچک و بی‌تأیید در سوئیچر
دکمه‌ی حذف حساب (که سمت سرور logout می‌کنه) ~۲۳px بود، درست کنار ردیفی که با تپ سوئیچ می‌کنه؛ روی گوشی یه تپ اشتباه = خروج کامل و تایپ دوباره‌ی رمز. حالا ناحیه‌ی لمس ≥۴۰px و قبل از حذف `confirmModal` (از مرحله‌ی ۵) می‌پرسه.

## 🟡 ۳) زوم خودکار iOS روی فیلدها
هیچ قاعده‌ای نبود که فونت فیلدها رو روی موبایل ≥۱۶px نگه داره؛ Safari آیفون روی هر فیلد با فونت کمتر از ۱۶px کل صفحه رو زوم می‌کنه (و برنمی‌گردونه) — روی همه‌ی فرم‌ها. به `responsive.css` (زیر ۸۰۰px) اضافه شد (با `!important` چون بعضی فیلدها فونت inline دارن؛ checkbox/radio/range/file مستثنی).

## چک‌شده و تمیز
- همه‌ی صفحه‌ها `viewport` دارن (`/index.html` فقط ریدایرکته). هیچ عرض ثابت ≥۳۰۰px بدون max-width توی `style` inline نیست.
- منطق سوئیچر (upsert/remove/۴۰۱ بدون پاک‌کردن حساب فعال هنگام افزودن حساب با رمز اشتباه) درسته.
- با این نسخه، **برنامه‌ی ۶ مرحله‌ای این دوره تموم شد** (v73–v77). مایگریشن جدید نداره.
