# دور سی‌ودوم — مرحله ۵ باگ‌گیری: یکدستی و بازخورد UX (۲۰۲۶-۰۹-۱۹) — v76

## ۱) پایان‌دادن به دیالوگ‌های خام مرورگر (`confirm()` / `prompt()`)
`modal.js` از قبل `promptModal` داشت (با کامنتِ صریح که دیالوگ خام OS «زشته و URL صفحه رو نشون می‌ده»)، ولی ۱۲ تا `confirm()` و ۱ تا `prompt()` هنوز مونده بود — یعنی حذف کلاس/درس/جلسه/تعطیلی/تکلیف/آزمون/فصل/دوره‌ی نمره‌دهی، انتشار آزمون، ارسال نهایی آزمون توسط دانش‌آموز و…
- `confirmModal(message, {title, okLabel, danger})` به `app.js` اضافه شد (Promise<boolean>). مستقل از `#modalOverlay` ساخته می‌شه، پس روی همه‌ی صفحات کار می‌کنه (از جمله `operations.html` که modal.js نداره) و فرمِ بازِ زیرش رو خراب نمی‌کنه (z-index بالاتر از modal و preview).
- Esc / کلیک روی پس‌زمینه / «لغو» = false. برای حذف‌ها فوکوس اولیه روی «لغو»ه (Enter اتفاقی چیزی پاک نمی‌کنه) و دکمه‌ی تأیید قرمزه. متن با `textContent` گذاشته می‌شه (امن).
- `renameSubject` ادمین هم از `prompt()` به `promptModal` رفت. الان هیچ `confirm(`/`prompt(` خامی تو کل پروژه نیست.
- منطق با یه stub از DOM تست شد: تأیید، لغو، Esc، backdrop، و جایگزینی دیالوگ قبلی وقتی دومی باز می‌شه.

## ۲) شکست‌های بی‌صدا (خطای سرور، بدون هیچ پیامی برای کاربر) — واقعی
Promise‌ی رد‌شده‌ی بدون catch برای کاربر نامرئیه. چند مورد مهم:
- والد: ثبت درخواست و **درخواست جلسه** (`parent/services.html`) — مثلاً وقتی بازه‌ی جلسه با جلسه‌ی دیگه تداخل داره، سرور درست رد می‌کرد ولی والد هیچی نمی‌دید.
- ادمین (`operations.html`): امانت کتاب، سال تحصیلی، پرونده‌ی دانش‌آموز، انضباطی، برنامه‌ی آزمون، کتاب، شهریه، اختصاص شهریه، تغییر وضعیت درخواست/جلسه، شروع ارتقا.
- دانش‌آموز: «بررسی پاسخ» در تمرین (۲ مسیر).
- معلم: تغییر وضعیت جلسه‌ی اولیا، علاقه‌مندی سؤال، ثبت/حذف مهارت سؤال. سوپرادمین: ذخیره‌ی اشتراک.
- راه‌حل: `guarded(fn)` (در `app.js`، خطا رو toast قرمز می‌کنه و rethrow نمی‌کنه) و معادل محلی `safe()` در operations.
- همچنین ۲ toast خطا در معلم (افزودن سؤال به آزمون) با استایل سبز «موفقیت» نمایش داده می‌شد → قرمز شد.
