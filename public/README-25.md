# قدم ۲۵ — پورت متادیتای بانک سؤال از دبستان (مورد ۱ از لیست مقایسه)

## چیزی که اضافه شد
پنج ستون جدید روی جدول `questions` (بانک سؤال معلم، همون‌جایی که سؤال‌های آزمون ساخته می‌شن):
- `chapter` — فصل (مثل «فصل ۴»)
- `topic` — مبحث (مثل «اندازه‌گیری»)
- `explanation` — توضیح تکمیلی که فقط بعد از پاسخ‌دهی دانش‌آموز معنا داره
- `tags` — برچسب‌ها، رشته‌ای جداشده با کاما (دقیقاً همون قرارداد ذخیره‌سازی دبستان)
- `difficulty` — یکی از `easy`/`medium`/`hard`، سمت سرور اعتبارسنجی می‌شه

Migration: `database/migrations/017_question_metadata.sql` — کاملاً افزایشی (ALTER TABLE با ستون‌های nullable)، هیچ سؤال قدیمی یا کد `SELECT *` موجود خراب نمی‌شه.

## چیزی که تغییر کرد
- `functions/api/teacher/questions.js` — POST و PUT حالا این ۵ فیلد رو می‌پذیرن، با یک تابع مشترک `readMetadata()` برای اعتبارسنجی (سقف طول برای فیلدهای متنی، enum برای سختی).
- `public/teacher/index.html` — فرم ساخت/ویرایش سؤال این ۵ فیلد رو داره؛ لیست بانک سؤال زیر متن هر سؤال یک خط کوچک نشون می‌ده (فصل · مبحث · سختی · #برچسب‌ها) فقط برای چیزهایی که واقعاً پر شدن.

## چیزی که عمداً اضافه نشد (خارج از دامنه‌ی همین قدم)
- **نمایش `explanation` به دانش‌آموز بعد از نتیجه‌ی آزمون** — الان `student/exam-result.js` فقط آمار کلی (تعداد درست/غلط/نیازمند بررسی) برمی‌گردونه، نه سؤال‌به‌سؤال. اضافه‌کردن نمایش توضیح یعنی ساخت یک صفحه‌ی «مرور پاسخ‌ها» جدید — این خودش یک فیچر جداست، نه بخشی از «اضافه‌کردن متادیتا». اگه بخوای، به‌عنوان یک قدم بعدی جدا انجامش می‌دیم.
- جستجو/فیلتر/علاقه‌مندی روی این متادیتا (مورد ۳ از لیست مقایسه) — قدم بعدی.
- نمایش فصل/مبحث به خود دانش‌آموز حین دادن آزمون — `toSafeQuestion()` در `student/exams.js` عمداً یک whitelist سخت‌گیرانه‌ست؛ فیلدهای جدید خودکار به دانش‌آموز درز نمی‌کنن چون اونجا لمس نشده.
