# دور سی‌وچهارم — رفع صفحه‌ی خالی «عملیات و امکانات» + جلسات اولیا + نمایش فرزندان والد (۲۰۲۶-۰۹-۱۹) — v78

## 🔴 ۱) صفحه‌ی «عملیات و امکانات» خالی می‌شد — باگ از تغییر خودم در v76
علت: در v76 تابع کمکی `safe()` رو اشتباهاً **داخل** تابع `load()` تعریف کرده بودم ولی خارج از اون هم صدا می‌زدمش → `ReferenceError: safe is not defined` → کل اسکریپت صفحه قبل از اجرای `load()` متوقف می‌شد و فقط تیتر می‌موند. `node --check` این نوع خطا (خطای «اسکوپ») رو نمی‌بینه، برای همین رد شده بود.
- **فیکس:** `safe()` به سطح بالای اسکریپت رفت.
- **جلوگیری از تکرار:** `tests/page-smoke.cjs` — همه‌ی صفحه‌ها رو با DOM ساختگی اجرا می‌کنه و خطای زمان‌اجرا در سطح بالا رو گزارش می‌ده (همین باگ رو دقیقاً پیدا کرد؛ الان روی ۱۶ صفحه: صفر خطا).

## ۲) جلسات اولیا: معلم فقط می‌دید — حالا خودش هم می‌تونه جلسه تعیین کنه
مشکل‌ها: (الف) فقط والد می‌تونست جلسه بسازه؛ (ب) منوی وضعیتِ معلم همیشه روی «درخواست» می‌موند و وضعیت واقعی رو نشون نمی‌داد، وضعیت هم انگلیسی خام بود؛ (پ) هیچ توضیحی نبود که چه کسی چه کاری می‌کنه.
- **جدید:** `POST /api/teacher/meetings` + `GET /api/teacher/meeting-options`. معلم دانش‌آموزی از کلاس‌های خودش (سال تحصیلی جاری) انتخاب می‌کنه، اگه بیش از یک والد وصل باشه والد رو انتخاب می‌کنه، زمان/مدت/موضوع می‌ده. جلسه با وضعیت «تأیید شده» ثبت می‌شه و به والد اعلان می‌ره + audit log. دانش‌آموزِ بدون والدِ متصل با برچسب «والدی متصل نشده» غیرفعال نشون داده می‌شه. بدون مایگریشن جدید (از دسترسی موجود `meetings.manage` استفاده می‌کنه).
- **صفحه‌ی معلم:** توضیح مسیر کار بالای صفحه؛ فرم «تعیین جلسه»؛ وضعیت فارسی با رنگ (منتظر پاسخ شما / تأیید شده / برگزار شد / لغو شده)؛ دکمه‌های مناسب هر وضعیت (تأیید/لغو، برگزار شد/لغو) با تأیید قبل از لغو؛ زمان به شمسی و نمایش مدت.
- **مسیر کلی حالا:** والد درخواست می‌ده *یا* معلم تعیین می‌کنه ← معلم تأیید/لغو/«برگزار شد» ← ادمین در «امکانات و مدیریت» می‌بینه.
- **دو باگ کنارش:** (۱) تداخل زمانی جلسه (تریگر DB) پیام «خطای داخلی سرور» می‌داد؛ حالا ۴۰۹ با متن روشن (برای هر مسیری که جلسه می‌سازه/وضعیت عوض می‌کنه). (۲) اعتبارسنجی مدت جلسه‌ی والد تا ۲۴۰ دقیقه اجازه می‌داد ولی CHECK دیتابیس فقط تا ۱۸۰ → ۵۰۰؛ هم‌سطح شد (۱۰ تا ۱۸۰).
- SQL جدید روی اسکیمای واقعی (تمام ۵۲ مایگریشن) در SQLite تست شد: والد چندگانه، دانش‌آموز بدون والد، تداخل، پشت‌سرهم‌بودن مجاز.

## ۳) ادمین ← والدین: فرزندان نشون داده می‌شن
قبلاً جدول فقط نام و نام کاربری داشت؛ بعد از «اتصال فرزند» مودال بسته می‌شد و فقط یه toast کوچیک که سه ثانیه بعد می‌رفت — هیچ اثری تو صفحه نبود.
- ستون «فرزندان» با چیپِ نام هر فرزند اضافه شد؛ «فرزندی متصل نشده» برای خالی‌ها.
- بعد از اتصال، لیست بلافاصله رفرش می‌شه و پیام «✓ «نام دانش‌آموز» به «نام والد» متصل شد» میاد.
- دانش‌آموزهایی که قبلاً وصل شدن تو انتخاب نیستن (قبلاً بی‌صدا دوباره «متصل شد» می‌گفت)؛ اگه همه وصل باشن پیام می‌ده.
- دکمه‌ی ✕ روی هر چیپ برای قطع اتصال (با تأیید) — API‌ش از قبل بود ولی UI نداشت.
