# قدم ۲۲ — رفع مشکل «تداخل نشست بین تب‌ها» + بازگردانی database_id

## ۱) مشکل: نمی‌شد هم‌زمان با نقش‌های مختلف تو تب‌های مختلف کار کرد
علتش این بود که نشست کاربر (`madrese_session`) با `localStorage` ذخیره می‌شد — که بین **همه‌ی تب‌ها و پنجره‌های همون مرورگر** مشترکه. یعنی اگه تو یک تب به‌عنوان معلم لاگین بودی، باز کردن `login.html` تو یک تب دیگه (برای ورود به‌عنوان دانش‌آموز) بلافاصله همون نشست معلم رو می‌دید و خودکار به داشبورد معلم ریدایرکت می‌کرد — همون رفتاری که گزارش کردی («صفحه ورود می‌زنم مستقیم می‌ره رو داشبورد معلم») و احتمالاً همون چیزیه که به‌نظر می‌رسید «قبل از زدن دکمه‌ی ورود خودکار وارد می‌شه».

**رفع شد:** `public/assets/js/api.js` حالا از `sessionStorage` به‌جای `localStorage` استفاده می‌کنه. `sessionStorage` مخصوص هر تب/پنجره‌ست، نه کل مرورگر — پس الان می‌تونی هم‌زمان تو یک تب معلم و تو تب دیگه دانش‌آموز باز کنی، کاملاً مستقل از هم.

**نکته‌ی مهم (trade-off عادی و مورد انتظار):** چون نشست دیگه بین تب‌ها مشترک نیست، هر تب تازه‌ای که باز می‌کنی باید دوباره لاگین کنی — این دقیقاً همون چیزیه که برای تست هم‌زمان چند نقش لازم داری، ولی یعنی برای استفاده‌ی روزمره‌ی خودت هم دیگه با باز کردن یک تب جدید خودکار لاگین نمی‌مونی (تا وقتی همون تب باز باشه لاگین می‌مونی، بستن تب = خروج از اون تب).

## ۲) بازگردانی database_id
`database_id` تو `wrangler.toml` دوباره به‌صورت placeholder برگشته بود. آیدی واقعی که فرستادی (`321359a5-fe92-4eb9-9e91-d68d0770d8dc`) رو مستقیم تو `wrangler.toml` همین زیپ گذاشتم. **از این به بعد، این فایل رو هم مثل بقیه‌ی پوشه‌ها تو مرحله‌ی جایگزینی کپی کن** (قبلاً به‌خاطر اینکه آیدی واقعی رو نداشتم، این فایل رو عمداً از لیست کپی حذف کرده بودیم؛ حالا که آیدی واقعی رو تو کد دارم، دیگه لازم نیست جداش کنیم).

فرمان Termux به‌روزرسانی شد (پایین همین پیام) — `wrangler.toml` رو هم اضافه کردم به مرحله‌ی کپی.
