# دور بیست‌ویکم — قابلیت جدید: مدیریت دوره‌های نمره‌دهی (۲۰۲۶-۰۹-۱۷) — v64

## قابلیت اضافه‌شده: دوره‌های نمره‌دهی (نوبت اول/دوم) کاملاً فعال شد

از دور ۱۷ (مرحله ۳) یادداشت شده بود که جدول `grade_periods` در همه‌جا استفاده می‌شه ولی هیچ‌جا امکان ساختنش نبود. این دور کامل ساخته شد:

### بک‌اند
- **migration جدید `050_grade_periods_permissions.sql`:** دو مجوز `grade_periods.view` و `grade_periods.manage` اضافه و به مدیر (مدیریت کامل) و معلم/دانش‌آموز/والد (فقط مشاهده، برای پر کردن فیلتر کارنامه) اعطا شد. **نکته‌ی مهم برای آینده:** مجوزهای جدید به‌طور خودکار به مدیر داده نمی‌شن — قبلاً تصور اشتباهی داشتم که مدیر با یک CROSS JOIN همه‌ی مجوزها رو خودکار می‌گیره؛ آن CROSS JOIN فقط یک‌بار، همون لحظه‌ی اجرای migration شماره ۲، روی مجوزهای وقت اجرا شد — هر مجوز جدید بعدی (مثل این یکی) باید صریحاً به هر نقش اعطا بشه، دقیقاً مثل تمام migrationهای قبلی این پروژه.
- **endpoint جدید `functions/api/admin/grade-periods.js`:** GET (لیست)، POST (ساخت با اعتبارسنجی تاریخ + جلوگیری از همپوشانی دو دوره)، PATCH (ویرایش)، DELETE (حذف — نمرات مرتبط با آن دوره به‌جای خطا یا حذف، فقط `grade_period_id`شان NULL می‌شه، به‌درستی شبیه‌سازی و تأیید شد). تاریخ شروع با ساعت ۰۰:۰۰:۰۰ و پایان با ۲۳:۵۹:۵۹ ذخیره می‌شه تا روز آخر دوره کامل حساب بشه (یک نکته‌ی ظریف تاریخ که از قبل در این پروژه یاد گرفته بودیم و رعایتش کردیم).
- `student/report-card.js` و `parent/grades.js`: یک گزینه‌ی صریح `grade_period_id=all` اضافه شد تا بشه «همه‌ی نمرات بدون فیلتر دوره» رو هم درخواست کرد، نه فقط دوره‌ی پیش‌فرض جاری.

### فرانت‌اند
- **پنل مدیر (`operations.html`):** یک کارت جدید «دوره‌های نمره‌دهی» — ساخت با نام+تاریخ شروع/پایان، لیست دوره‌های موجود، حذف.
- **کارنامه‌ی دانش‌آموز و والد:** یک منوی کشویی برای انتخاب دوره (یا «همه‌ی نمرات») اضافه شد؛ نام دوره‌ی واقعی حالا به‌جای متن ثابت «دوره‌ی جاری» نمایش داده می‌شه.

### تست
منطق تشخیص همپوشانی دوره‌ها و تشخیص «دوره‌ی جاری» با شبیه‌سازی مستقیم روی یک دیتابیس SQLite واقعی (ساخته‌شده از هر ۵۰ migration) تأیید شد. هر ۵۰ migration بدون خطا روی هم اجرا می‌شن.
