# دور سی‌ویکم — مرحله ۴ باگ‌گیری: ورودی‌های خصمانه/نامعتبر (۲۰۲۶-۰۹-۱۹) — v75

## 🔴 یافته‌ی واقعی: Stored XSS از طریق لوگوی مدرسه (`logo_data`)
همون خانواده‌ی باگ `answer_data` در v62 — فقط این بار توی فیلدی که «متن کاربر» به نظر نمی‌رسید.
- `PATCH /api/admin/school` فقط **طول** لوگو رو چک می‌کرد، نه **فرمت**. مقدارِ شامل `"` می‌تونست از `<img src="...">` بیرون بزنه.
- لوگو توی `app.js` (`initShell`) روی **هر صفحه‌ی هر نقش** (معلم/دانش‌آموز/والد/ادمین) بدون escape تو `<img src>` ریخته می‌شد → یه ادمین مدرسه (یا حساب ادمین هک‌شده) می‌تونست JS رو تو مرورگر همه‌ی کاربرای همون مدرسه اجرا کنه (و با ماندگاری ورود + سوئیچر حساب، توکن‌ها توی localStorage‌ان → اثرش بزرگ‌تر از قبل).
- **فیکس (دو لایه):** بک‌اند — regex سخت‌گیرانه‌ی data-URI تصویر (`^data:image/...;base64,...$`) + چک `typeof` روی `name`/`primary_color`/`logo_data`؛ فرانت — `escapeHtml()` روی هر دو محل رندر (`app.js` و `admin/index.html`) تا مقدارهای بد که قبلاً ذخیره شدن هم بی‌اثر بشن.
- تست شد: مقدار عادی پذیرفته می‌شه؛ `"…onerror=…`، `javascript:` و `data:text/html` رد می‌شن.

## چک‌شده و تمیز
- اسکن کل فرانت برای هر `${…}` بدون escape روی فیلدهای متنی: فقط همین لوگو مشکل واقعی بود؛ بقیه یا ثابت‌ان (`f.name/f.url` در operations، `item.label` در navigation) یا از مسیر `textContent` می‌رن (`openModal` عنوان رو با `textContent` می‌ذاره؛ `toast` هم همین‌طور).
- `escapeAttr` (JSON.stringify + entity-escape) داخل `onclick` امنه.
- سقف تعداد ردیف CSV import (`MAX_ROWS`) از قبل هست.
