# v47 (2026-09-15) — بازبینی کامل پروژه برای رگرسیون (بعد از v46)

بعد از v46، یک دور کامل «آیا چیزی رو خراب کردیم؟» روی کل پروژه (نه فقط فیچرهای جدید) انجام شد. روش کار: مقایسه‌ی خودکار هر مسیر API که فرانت‌اند صدا می‌زنه با فایل‌های بک‌اند، چک هر تابعی که `onclick`/`onsubmit` صداش می‌زنه، تطبیق هر permission استفاده‌شده با گرنت‌هایی که مایگریشن‌ها می‌دن، دیف کامل فایل‌های اصلیِ قدیمی (آزمون/تکلیف/نمرات/حضورغیاب/پیام/اطلاعیه) با نسخه‌ی قبل، و — مهم‌تر از همه — **اجرای واقعی کل ۴۹ مایگریشن روی یک SQLite واقعی (نه فقط خوندن کد) به‌همراه شبیه‌سازی چند تراکنش واقعی** (ساخت دانش‌آموز، ارتقا، پرداخت شهریه، امانت کتاب، بازپخش کد 2FA، ابطال Session) تا مطمئن بشیم تریگرهای امنیتی جدید با کدهای قدیمی و جدید هر دو واقعاً کار می‌کنن، نه فقط از نظر منطقی درست به‌نظر می‌رسن.

## 🔴 رگرسیون واقعی پیدا و اصلاح شد
**ساخت دانش‌آموز جدید (تکی یا ایمپورت CSV) از همون لحظه‌ای که مدرسه یک سال تحصیلی دوم داشته باشه، ممکنه کاملاً خراب بشه.**

چرا: دانش‌آموز همیشه توی سال تحصیلی **جاری** ثبت‌نام می‌شه، اما دراپ‌داون انتخاب کلاس همه‌ی کلاس‌های همه‌ی سال‌ها رو نشون می‌داد. اگه مدیر کلاسی از یک سال غیرِ جاری انتخاب می‌کرد، یکی از تریگرهای integrity جدید (`047_deep_integrity_hardening.sql`) کل عملیات رو با خطای خام `student enrollment ownership/year mismatch` رد می‌کرد. با شبیه‌سازی واقعی این سناریو (ساخت یه سال تحصیلی دوم + کلاس توش + تلاش برای ثبت دانش‌آموز) این رفتار عیناً بازتولید شد.

**اصلاح شد:**
- `admin/students.js` و `admin/students-import.js`: قبل از هر کاری چک می‌کنن کلاس انتخابی مال سال جاریه؛ اگه نبود، یک پیغام فارسی روشن می‌دن (نه خطای خام دیتابیس).
- `GET /api/admin/classes?current_year=1` اضافه شد؛ دراپ‌داون کلاس توی فرم «افزودن دانش‌آموز» و «ایمپورت گروهی» فقط از این استفاده می‌کنه. جاهای دیگه (مدیریت کلاس‌ها، پیش‌نمایش ارتقا) عمداً دست‌نخورده موند چون اونجا باید کلاس‌های همه‌ی سال‌ها دیده بشن.
- با شبیه‌سازی مجدد تأیید شد که سناریوی درست (کلاس سال جاری) درست کار می‌کنه و سناریوی غلط دیگه اصلاً به آن تریگر نمی‌رسه.

## ✅ چیزهایی که با اجرای واقعی (نه فقط خوندن کد) تأیید شدن
- کل توالی ۴۹ مایگریشن + `seeds.sql` روی یک دیتابیس خالی بدون خطا اجرا می‌شه (ترتیب/وابستگی ستون‌ها مشکلی نداره).
- منطق ارتقا (هم auto-match هم mapping صریح) با یک سناریوی واقعی (۲ دانش‌آموز، یکی هم‌نام یکی نیازمند ارتقای پایه‌ی واقعی) دقیقاً همون‌طور که باید کار کرد.
- پرداخت شهریه: پرداخت جزئی، تلاش برای پرداخت بیش از مانده (رد شد)، پرداخت باقی‌مانده تا صفر شدن بدهی — همه درست.
- امانت کتاب: کاهش/افزایش صحیح `available_copies`، رد امانت وقتی نسخه‌ای باقی نمونده.
- بازپخش کد 2FA: کد تکراری و کد قدیمی‌تر رد می‌شن، کد جدیدتر قبول می‌شه.
- «خروج از همه دستگاه‌ها»: فقط نشست‌های دیگر باطل می‌شن، نشست فعلی دست‌نخورده می‌مونه.
- مسیرهای API فرانت‌اند (۱۲۵ مورد) همه به یک فایل بک‌اند واقعی می‌رسن؛ هیچ تابع تعریف‌نشده‌ای صدا زده نمی‌شه؛ هیچ permission بی‌صاحبی نیست.
- تغییرات این batch روی فایل‌های قدیمی اصلی (آزمون/تکلیف/نمرات/حضورغیاب) همه یا سخت‌گیری بیشتر (اضافه‌کردن `school_id`) بودن یا اصلاح باگ واقعی — هیچ‌کدوم چیزی رو نمی‌شکنه.
