# قدم ۳۰ — نوع سؤال «جای‌خالی» (fill_blank)

## چیزی که اضافه شد
- `database/migrations/020_fill_blank.sql` — ستون `grading_mode` (`auto` | `manual`) روی `questions` و `question_versions`.
- نوع سؤال جدید `fill_blank` تو `teacher/questions.js`.
- `correct_text` (ستون از قبل موجود) برای این نوع، لیستی از پاسخ‌های قابل‌قبول با کاما جداشده رو نگه می‌داره (مثل «تهران, تهرون»).
- تصحیح خودکار با نرمال‌سازی متن فارسی (همون `_shared/search-normalize.js` که برای جستجو پورت شده بود) — یعنی «كتاب»/«کتاب» یا فاصله‌های اضافه مشکلی درست نمی‌کنن.
- **معلم خودش تعیین می‌کنه خودکار باشه یا دستی** — یک select تو فرم سؤال. اگه دستی رو انتخاب کنه، دقیقاً مثل `short_answer`/`long_answer` تو صف «تصحیح دستی» میفته (بدون هیچ تغییری تو `teacher/grading.js`، چون اون endpoint از قبل عمومی بود و بر اساس نوع سؤال فیلتر نمی‌کرد).
- صفحه‌ی نتیجه‌ی آزمون دانش‌آموز (قدم ۲۷) هم برای این نوع، پاسخ خودش + پاسخ قابل‌قبول رو نشون می‌ده.

## محدودیت صادقانه (به کاربر هم گفته شد)
تصحیح خودکار یک تطبیق **دقیق متن** هست، نه فهم معنا. یعنی برای سؤال‌هایی با یک جواب کوتاه و مشخص (اسم، عدد، تاریخ) خوبه؛ برای سؤال‌های باز با چند جواب ممکن مناسب نیست — برای اون‌ها معلم باید حالت «دستی» رو انتخاب کنه.

## سازگاری با versioning (قدم ۲۶)
`grading_mode` هم مثل بقیه‌ی فیلدهای مؤثر بر تصحیح، تو `question_versions` فریز می‌شه — یعنی اگه معلم بعداً حالت تصحیح یک سؤال رو از خودکار به دستی (یا برعکس) عوض کنه، آزمون‌های قبلاً ساخته‌شده با همون قاعده‌ی قبلی تصحیح می‌مونن.
