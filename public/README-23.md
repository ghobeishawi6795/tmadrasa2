# قدم ۲۳ — یک لایه‌ی جدید: سوپرادمین (بالاتر از مدیر مدرسه)

## چی اضافه شد
یک نقش پنجم، بالاتر از مدیر مدرسه: **سوپرادمین** — یک حساب که به هیچ مدرسه‌ی خاصی تعلق نداره و همه‌ی مدرسه‌های ثبت‌شده رو می‌بینه.

### قابلیت‌ها (طبق چیزی که خواستی)
- **مدرسه‌ها**: فهرست کامل همه‌ی مدرسه‌ها + تعداد دانش‌آموز/معلم/والد/مدیر هرکدام + آخرین ورود موفق. ساخت مدرسه‌ی جدید (خالی، بدون مدیر — مدیرش رو باید جدا با `register.html` بسازی چون اون فرآیند تغییر نکرده). فعال/غیرفعال کردن هر مدرسه — **غیرفعال کردن الان واقعاً کار می‌کنه**: اگه مدرسه‌ای غیرفعال باشه، هیچ‌کدوم از کاربراش (مدیر/معلم/دانش‌آموز/والد) نمی‌تونن وارد بشن، حتی اگه حساب خودشون فعال باشه.
- **پیام‌رسانی**: سوپرادمین می‌تونه از صفحه‌ی مدرسه‌ها، دکمه‌ی «پیام» رو بزنه و مستقیم به مدیر(های) اون مدرسه پیام بده. مدیر همون پیام رو تو صفحه‌ی «پیام‌ها»ی داشبورد خودش می‌بینه (با عنوان «پیام از هدف (سوپرادمین)») و می‌تونه جواب بده — بدون هیچ تغییری تو تجربه‌ی مدیر.
- **گزارش کلی**: صفحه‌ی داشبورد سوپرادمین مجموع کلی (تعداد مدرسه‌ها، فعال/غیرفعال، مجموع دانش‌آموز/معلم/والد در کل پلتفرم) رو نشون می‌ده.
- مثل بقیه‌ی داشبوردها: «راهنما» و خروج داخل منو هم داره.

## ساخت اولین حساب سوپرادمین
یک صفحه‌ی موقت `public/register-superadmin.html` اضافه شد (دقیقاً مثل `register.html` قدیمی) — فقط نام، نام‌کاربری و رمز عبور می‌خواد، هیچ ربطی به مدرسه نداره. بعد از ساخت حساب(ها)، از `/superadmin/login.html` وارد شو. **طبق قرارمون، بعد از ساخت حساب(های) لازم، این فایل رو از روی گیت‌هاب حذف کن.**

## نکات فنی (برای من، اگه لازم شد برگردم بهش)
- سوپرادمین چون به هیچ مدرسه‌ی واقعی تعلق نداره ولی جدول `users` ستون `school_id` رو الزامی می‌خواد، یک «مدرسه‌ی سیستمی» با `id=0` (نام: «سیستم (سوپرادمین)»، همیشه غیرفعال) تو مایگریشن جدید ساخته شده — این مدرسه هیچ‌جا تو لیست‌های سوپرادمین نشون داده نمی‌شه.
- ورود سوپرادمین از یک صفحه‌ی جدا (`superadmin/login.html`) انجام می‌شه که برخلاف صفحه‌ی ورود معمولی، فیلد «شناسه مدرسه» نداره (همیشه پشت‌صحنه ۰ می‌فرسته).
- پیام‌رسانی سوپرادمین از همون جدول‌های پیام‌رسانی موجود استفاده می‌کنه (نه چیز جدید) — فقط یک گفتگوی گروهی با `school_id` مدرسه‌ی مقصد ساخته می‌شه و سوپرادمین بهش اضافه می‌شه؛ همین باعث می‌شه از سمت مدیر مدرسه بدون هیچ تغییری قابل مشاهده و پاسخ‌گویی باشه.
- **⚠️ یک قدم دستی لازم داری**: مایگریشن جدید `015_super_admin.sql` رو باید تو کنسول D1 اجرا کنی (مثل همیشه).
- در ضمن یک باگ واقعی و قدیمی هم پیدا و رفع شد: ویرایش پیام (`PUT /api/messages/messages`) به‌خاطر یک متغیر تعریف‌نشده همیشه خطا می‌داد — رفع شد.

## مایگریشن لازم (اجرا کن تو D1)
```sql
INSERT INTO schools (id, name, active) VALUES (0, 'سیستم (سوپرادمین)', 0);
INSERT INTO roles (key, label) VALUES ('super_admin', 'سوپرادمین');
INSERT INTO role_permissions (role_id, permission_id)
SELECT (SELECT id FROM roles WHERE key = 'super_admin'), id
FROM permissions WHERE key IN ('messages.view', 'messages.create');
```
