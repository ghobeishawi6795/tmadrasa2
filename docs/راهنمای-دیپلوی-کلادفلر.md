# راهنمای ساده‌ی دیپلوی «مدرسه» روی Cloudflare (Pages + D1)

## نکته‌ی مهم اول — «Secret» لازم نیست
پروژه‌ی مدرسه، برخلاف Tset/شمام، از توکن‌های امضاشده (JWT/HMAC) استفاده نمی‌کنه — توکن‌های نشست (session) به‌صورت تصادفی ساخته می‌شن و هش‌شده (SHA-256) تو خودِ دیتابیس D1 ذخیره می‌شن. یعنی:
- **هیچ متغیر محیطی (Environment Variable) یا Secret ۴۴ کاراکتری لازم نیست.**
- چیزی شبیه `ATTEMPT_SECRET` که تو Tset لازم بود، اینجا وجود نداره.
- تنها چیزی که لازم داری، اتصال دیتابیس D1 هست (پایین توضیح داده شده).

## قدم ۱ — ساخت دیتابیس D1
1. وارد **Cloudflare Dashboard** شو.
2. از منوی سمت چپ برو به **Workers & Pages → D1**.
3. روی **Create database** بزن.
4. یک اسم بذار — مثلاً `madrese` (هرچی باشه مهم نیست، فقط خودت بدونی).
5. بعد از ساخته‌شدن، وارد صفحه‌ی همون دیتابیس شو.

## قدم ۲ — اجرای Migration ها از کنسول D1
هر دیتابیس D1 یک تب به اسم **Console** داره (همون‌جا که کوئری SQL می‌تونی بزنی).

باید فایل‌های داخل پوشه‌ی `database/migrations/` رو **به ترتیب شماره** (از 001 تا 014) کپی کنی و تو کنسول پیست و اجرا (Execute) کنی. بعدش هم فایل `database/seeds.sql` رو اجرا کن (این نقش‌ها و دسترسی‌های پایه رو می‌سازه).

⚠️ نکات مهم:
- ترتیب اجرا مهمه — نباید 005 رو قبل از 004 اجرا کنی.
- هر فایل رو کامل کپی کن، نه فقط یک خط.
- اگه یک migration رو دوبار اجرا کنی و خطای «already exists» بگیری، یعنی قبلاً اجرا شده — نگران نباش، برو سراغ بعدی.
- آخرین migration فعلی (`014_holidays_branding.sql`) رو حتماً باید اجرا کنی، وگرنه بخش تنظیمات/برندینگ/تعطیلات کار نمی‌کنه.

## قدم ۳ — ساخت پروژه‌ی Pages و اتصال D1
1. برو به **Workers & Pages → Create → Pages**.
2. پروژه رو از روی گیت‌هاب ریپازیتوریت وصل کن (Connect to Git).
3. تنظیمات build:
   - **Build output directory:** `public`
   - نیازی به build command نیست (پروژه استاتیک + Pages Functions هست).
4. بعد از اولین دیپلوی، برو به **Settings → Functions** همون پروژه‌ی Pages.
5. تو بخش **D1 database bindings** یک binding جدید اضافه کن:
   - **Variable name:** دقیقاً `DB` بنویس (حروف بزرگ — کد پروژه دقیقاً همین اسم رو می‌خونه)
   - **D1 database:** همون دیتابیسی که تو قدم ۱ ساختی رو انتخاب کن
6. ذخیره کن و یک **Redeploy** بزن تا binding اعمال بشه.

## قدم ۴ — ساخت اولین حساب مدیر
نیازی به دستکاری مستقیم دیتابیس نیست. کافیه یک درخواست به این آدرس بزنی (یا یک فرم ثبت‌نام تو خودِ سایت اگه ساخته باشیم):

```
POST /api/auth/register-school
{
  "school_name": "...",
  "admin_full_name": "...",
  "username": "...",
  "password": "..."
}
```

این خودش هش پسورد رو می‌سازه و اولین مدرسه + حساب مدیر رو می‌سازه.

## چک‌لیست خلاصه
- [ ] دیتابیس D1 ساخته شد
- [ ] همه‌ی migration ها (001 تا 014) به ترتیب اجرا شدن
- [ ] `seeds.sql` اجرا شد
- [ ] پروژه‌ی Pages به گیت‌هاب وصل شد، `public` به‌عنوان output directory
- [ ] Binding به اسم دقیق `DB` به دیتابیس D1 وصل شد
- [ ] بعد از اتصال binding، یک بار Redeploy زده شد
- [ ] اولین حساب مدیر از طریق `register-school` ساخته شد
- [ ] **Secret لازم نیست — رد شو از این مرحله**
